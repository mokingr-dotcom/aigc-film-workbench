# 安全剧本重分析与逐场确认

## 目标

让创作者可以反复修改剧本、重新使用本地解析或 AI 导演分析，而不会覆盖已经制作过的场次、角色与场景参考图、镜头提示词、生成状态或锁定成果。

本功能服务于“剧本 -> 场次 -> 镜头 -> 外部生成”的制作主链。它不判断故事好坏，也不自动接受 AI 的创作结论。

## 已选方案

采用“逐场差异确认 + 默认保护生产数据”。

备选方案及取舍：

1. 整份剧本一次替换：实现快，但会误删已制作内容，不采用。
2. 逐场确认并默认保留生产数据：用户能安全修改剧本，也能看懂影响范围，采用。
3. 自动智能合并所有字段：看似省事，但会猜测用户意图，无法保证资产与镜头连续性，不采用。

## 用户行为

1. 用户粘贴、上传或用 AI 重新分析剧本。
2. 系统生成“重分析草稿”，不会修改正式项目。
3. 页面显示逐场结果：新增、剧本更新、原稿未出现、受保护。
4. 用户可针对每一场选择保留原场或采用剧本更新。
5. 点击确认后，系统只应用已选择的变化，并保留所有被保护的制作数据。

## 匹配规则

1. 先用场景身份（标题、地点、时间）匹配。
2. 未匹配时，用场号匹配。
3. 一条正式场次最多匹配一条新草稿，匹配顺序稳定。
4. 无匹配的新草稿是新增场次。
5. 未被新草稿匹配的正式场次标为“原稿未出现”，默认保留，不删除。

## 逐场决策

每条重分析结果都产生一个可序列化的决策：

```text
sceneDecision
  proposedSceneId
  existingSceneId | null
  kind: add | update | retained
  action: add | update-story | keep-existing | skip-proposed
  protected: boolean
  reasons: string[]
```

默认动作：

- `add`：默认 `add`，用户可改为 `skip-proposed`，不写入该条新草稿。
- 有匹配且内容变化：默认 `update-story`。
- 原稿未出现：默认 `keep-existing`。

`protected` 为真时，场次仍可使用 `update-story`，但绝不自动整场替换。保护条件包括：场次引用资产、场次已有参考图、场次有非待生图镜头状态、已有镜头提示词编辑，或场次已经锁定。

## 合并规则

`update-story` 只更新剧本叙事层：`number`、`title`、`setting`、`time`、`storyBeat`、`sourceExcerpt`、`emotion`、`action`。

它始终保留：

- 原始 `id`；
- `assetIds` 与项目资产账本；
- `videoCard`、`visualOverride` 与导演分析；
- 原镜头数组、每镜目标模型、提示词卡、状态和后续生成记录；
- 原场次锁定状态。

新场次按解析结果创建。原稿未出现的场次保留在原顺序，并显示为尚未与新剧本匹配，而不是被删除。

## 页面

剧本入口的草稿预览升级为差异确认面板：

- 统计新增、剧本更新、保留原场、受保护场次的数量；
- 每场显示场号、标题、变更类型和保护理由；
- 每条可在“采用剧本更新 / 保留当前制作场”之间切换；
- 确认按钮显示将应用的场次数，而不是笼统的“确认写入正式分镜”。

没有已存场次时，保留现有的一键确认体验，不增加额外操作。

## 错误与边界

- 分析失败、AI 返回无效结构或用户取消时，不改动正式项目。
- 一次重分析草稿只对应当前项目和当前剧本草稿；编辑剧本后旧草稿立即失效。
- API 密钥继续只存在本次页面输入，不写入项目。
- 不删除资产 Blob；场次保留或更新不触发资产清理。
- 本期不做整场“强制替换”、冲突自动解决、AI 质量评分或外部生成 API。

## 验收

1. 重分析一场已锁定参考图、镜头状态和提示词的场次后，默认只更新叙事层，其余数据保持不变。
2. 原稿未出现的正式场次仍存在，默认保留。
3. 新场次可加入；用户改为保留当前场时，不写入该新增或更新。
4. 相同场号但标题变化时仍能得到可理解的“剧本更新”而不是删除加新增。
5. 本地与 AI 分析共用同一个差异确认和合并逻辑。
6. 旧项目迁移不丢失数据；`prompt-generator.test.js` 全量通过。
