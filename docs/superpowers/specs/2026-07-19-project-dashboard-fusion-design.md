# 影视项目桌面融合设计规格

## 决策摘要

项目默认入口采用用户确认的“制片项目台效率 + 克制电影影像感”融合方向。页面服务于导演、摄影师和 AIGC 创作者的长期制作，不承担营销落地页职责。

- 信息结构以项目管理为主，影像表达为辅，目标比例约为 60% / 40%。
- 保留左侧项目导航、中间项目内容、右侧当前项目详情三栏。
- 电影画面集中出现在当前项目横幅、当前项目封面和项目缩略图，不使用占据半屏的营销式大 Hero。
- 项目进度与六个工作台快捷入口同时存在，创作者可自由跳转，不强制线性流程。
- 用户确认的视觉稿位于 `.superpowers/brainstorm/4765-1784444857/content/project-dashboard-fusion-final.html`；实施时以该稿作为唯一视觉基准，项目卡片的影像槽按本规格修正为严格 16:9。

本规格细化并覆盖 `2026-07-17-project-center-design.md` 中“独立项目主页”的视觉与首屏结构；快速项目弹窗、数据兼容和项目安全规则继续沿用原规格。

## 产品目标

1. 用户打开产品后，能立即看到当前项目、制作进度、最近项目和下一步操作。
2. 一个项目统一承载影调、运镜、角色定妆、海报、画面反推和音乐配乐六个工作台状态。
3. 项目页面具有明确的电影影像气质，同时保持高频生产工具所需的阅读效率。
4. 为未来账号、云同步和订阅权限预留边界，但本阶段继续使用本地数据，不接登录、支付或模型 API。

## 首屏结构

### 顶部全局导航

- 产品名保持“AIGC电影视觉工作台”。
- “项目桌面”成为六个工作台之前的独立入口和默认入口。
- 保留影调、15 秒运镜、角色定妆、海报、画面反推、音乐配乐入口。
- 右侧保留全站搜索、当前项目和项目中心操作。
- 项目桌面激活时沿用深炭色导航、暖白文字和琥珀下划线，不改变其他工作台各自已确认的局部主题。
- 项目桌面是产品视图，不是第七个创作工作台，不进入 `workspaces` 数据，也不得覆盖项目的 `activeWorkspace`。
- 直接打开根地址时进入项目桌面；带 `?workspace=tone|camera|casting|poster|reverse|music` 的深链接继续直接进入指定工作台。

### 左侧项目导航

- 顶部显示“本地项目库”、项目总数和自动保存状态。
- 分类为全部项目、最近使用、已收藏和本地备份，并显示真实数量。
- 下方提供模板资料库和项目设置入口。
- 选中状态同时使用左侧色线、背景和字重表达，不只依赖颜色。

### 中间项目内容

中间区域按以下顺序组织：

1. 当前项目影像横幅。
2. 六阶段制作状态。
3. 最近项目列表。

当前项目横幅使用约 16:5 的克制横向电影画面，叠加项目名、类型、画幅、预计时长、当前影调摘要和“继续创作”操作。横幅不超过中间可视区高度的 24%，保证进度和最近项目仍在首屏可见。

六阶段依次为影调、角色、运镜、海报、画面反推和配乐。每项只显示“未开始 / 已设置 / 无法读取”、一行摘要和当前阶段强调，不显示伪精确完成百分比。

最近项目使用两列横向卡片。卡片包含严格 16:9 影像缩略图、项目名、类型、画幅、时长、三项视觉摘要和已设置工作台数量。单击卡片只负责选中并更新右栏；进入工作台必须使用卡片内独立的“继续创作”操作，避免单击、双击和触屏手势冲突。

### 右侧当前项目详情

- 显示项目名、收藏、类型、时长和更新时间。
- 使用一张完整 16:9 项目封面，画面内只保留画幅和影调版本等极少元数据。
- 主操作是进入项目最后使用的工作台。
- 六个工作台以 2 × 3 状态网格显示标题和一行摘要。
- 底部“下一步建议”由确定性状态规则生成，例如优先提示当前未完成阶段；不得伪装成 AI 判断。

## 轻量新建项目

首次使用时，项目库根级 `onboardingComplete` 为 `false`，项目桌面把系统自动创建的“未命名电影项目”作为初始草稿并显示“新建影视项目”面板。提交后直接补全并使用这个草稿，将 `onboardingComplete` 设为 `true`，不额外生成第二个项目。系统继续保持“至少存在一个项目”的现有安全规则，不引入真正的零项目存储状态。

新建面板只要求：

- 项目名称，1–60 个字符。
- 影片类型，默认“剧情”。
- 画幅，默认“16:9”。
- 预计时长，使用数值和“秒 / 分钟”单位控件；允许留空，填写时必须换算为 1–86400 的整数秒。

创建成功后直接进入新项目桌面。其余影调、角色、镜头和声音信息在对应工作台中完成，不增加多步骤向导。

项目元数据扩展为：

```js
{
  favorite: false,
  lastOpenedAt: "ISO-8601 timestamp",
  activeWorkspace: "tone",
  productionMeta: {
    type: "drama",
    aspectRatio: "16:9",
    estimatedDurationSeconds: null
  }
}
```

旧项目缺失这些字段时补默认值，不改变项目 ID，不覆盖六个工作台现有状态。`activeWorkspace` 继续只允许六个创作工作台 ID；项目桌面自身的筛选、选中和滚动上下文存储在项目库根级 `dashboardView`，不写入单个项目。

```js
{
  onboardingComplete: false,
  dashboardView: {
    category: "all",
    sort: "updated-desc",
    search: "",
    selectedProjectId: "project-id",
    scrollTop: 0
  }
}
```

新创建的全新项目库使用 `onboardingComplete: false`。现有项目库和旧备份缺失该字段时迁移为 `true`，避免老用户因项目名称相同而重新进入首次引导；导入任何包含有效项目的备份后也设为 `true`。

`dashboardView` 缺失或字段非法时逐项回退默认值；导入旧备份时补默认值，导入新备份时只接受已知分类、排序和有效项目 ID。

## 工作台摘要边界

新增独立纯读摘要层，每个适配器统一返回：

```js
{
  status: "empty" | "configured" | "unreadable",
  title: "用户可读的核心选择",
  detail: "一行关键参数",
  workspace: "tone | camera | casting | poster | reverse | music",
  actionLabel: "打开或继续操作的短标签"
}
```

- 摘要层只读取项目数据，不修改工作台状态。
- 影调读取已选风格、光影和色调。
- 运镜读取案例、时间轴、画幅和调度。
- 角色读取身份描述、参考素材和保存版本。
- 海报读取用途、主体、标题和模板。
- 画面反推读取参考图、八维校准和任务设置。
- 配乐读取案例、用途、情绪、配器和目标模型。
- 损坏或未知版本返回 `unreadable`，项目仍可显示和导出。
- `workspace` 必须是固定工作台 ID，`actionLabel` 不允许包含模型生成内容。

## 影像来源

第一阶段不增加项目封面上传，也不向 `localStorage` 写入 Base64 图片。

影像按以下优先级选择：

1. 项目已有海报模板或角色参考图的可恢复本地资产。
2. 项目所选影调或类型对应的本地参考图。
3. 产品内置的本地电影占位图。

页面不得依赖远程图片。素材失效时显示带项目名和影调色条的本地封面，不出现破图图标或空白大块。

封面解析与摘要解析分离：`project-summary.js` 保持同步纯读，不读取 Blob。独立的异步封面解析器按需访问角色资产存储，创建的 Object URL 必须在项目切换、卡片移出结果集和页面销毁时释放。加载期间使用稳定尺寸的本地占位面，异步结果返回前必须核对项目 ID，防止旧请求覆盖新项目封面。

## 页面状态与交互

- 默认选中当前项目；当前项目不存在时选中最近更新项目。
- 搜索按项目名实时过滤；筛选与排序返回工作台后保持。
- 收藏操作即时更新左侧数量和项目卡片，不改变当前项目。
- 从项目桌面进入工作台时记录项目的 `activeWorkspace` 和 `lastOpenedAt`。
- 当当前视图是项目桌面时，自动保存不得把 `activeWorkspace` 改成 `projects`。
- 工作台返回项目桌面后，恢复原筛选、滚动位置和选中项目。
- 删除、导入、批量备份继续放在完整项目管理操作中，不进入高频首屏主操作区。
- 删除必须二次确认，不允许删除唯一项目。

## 错误与空状态

- 本地存储失败：保留内存状态，顶部显示“未能保存到本地”，不得显示“已保存”。
- 工作台摘要无法读取：对应状态显示“无法读取”，其他工作台正常显示。
- 封面资产缺失：回退到本地生成封面，不阻断项目操作。
- 搜索无结果：显示当前筛选条件和“清除筛选”。
- `onboardingComplete: false` 的初始草稿：显示轻量新建和导入备份入口，不展示虚假的制作进度。
- 导入失败：不覆盖现有项目，显示结构错误原因。

## 视觉系统

- 全局背景为浅冷灰，内容面为暖白，顶部为深炭黑。
- 主操作使用低饱和灰绿，当前阶段和选中线使用琥珀色，错误使用暗酒红。
- 项目卡片圆角不超过 4px，不使用卡片内嵌套卡片和大面积阴影。
- 标题采用宋体或衬线回退，表单和正文采用无衬线中文字体；字间距固定为 0。
- 真实电影画面保持完整构图，横幅采用约 16:5，项目封面和缩略图采用 16:9，默认 `object-fit: cover` 并为关键主体设置稳定焦点。
- 页面禁止霓虹、光球、装饰性渐变、纯科幻控制台和营销式大标题。

## 响应式

- `>= 1280px`：左侧 180–208px，中间弹性区，右侧 360–420px，完整三栏。
- `1024–1279px`：左侧收窄为图标加文字导航，右侧 320–350px，中间项目卡片维持两列。
- `820–1023px`：隐藏左侧常驻栏，筛选进入顶部菜单；右侧详情变为可打开抽屉。
- `< 820px`：当前项目横幅、制作阶段、项目卡片单列；详情使用全宽抽屉；六阶段允许横向滚动但必须显示当前阶段。
- 所有断点不得出现页面横向溢出、文字遮挡、操作不可达或影像比例失真。

## 可访问性

- 顶部入口使用 `tablist` / `tab`，项目分类使用导航语义。
- 项目卡片支持键盘选中、打开和收藏；收藏具有明确 `aria-pressed`。
- 项目列表采用单选语义；卡片本体不是嵌套按钮，卡片内部“继续创作”和收藏是可独立聚焦的操作。
- 当前阶段、已设置和错误状态同时提供文字。
- 所有操作具有可见焦点，抽屉和弹窗管理焦点并支持 `Escape`。
- 支持 `prefers-reduced-motion`；动效只用于状态切换和抽屉，不影响内容读取。

## 实施边界

建议将项目桌面拆为以下独立模块：

- `project-summary.js`：六个工作台纯读摘要适配器。
- `project-cover.js`：异步封面选择、资产恢复、竞态保护和 Object URL 生命周期。
- `project-dashboard.js`：筛选、选择、创建、收藏和导航控制器。
- `project-dashboard.css`：仅作用于项目桌面的视觉与响应式规则。
- `workspace-core.js`：增加项目桌面路由和持久化接口，不承载项目桌面渲染细节。

必须复用现有项目存储、导入导出和角色资产清理逻辑。不得再创建一套平行项目数据库。

项目桌面的确定性“下一步建议”按以下顺序计算：

1. 有 `unreadable` 状态时，提示打开对应工作台检查数据。
2. 否则优先提示项目 `activeWorkspace` 对应的当前创作任务。
3. 当前任务已配置且存在空工作台时，按影调、角色、运镜、海报、画面反推、配乐的软顺序提示第一个空项。
4. 六项均已配置时，提示检查和导出项目，不显示“100% 完成”。

该顺序只影响建议文案，不锁定入口，也不阻止用户自由跳转。

## 测试与验收

### 数据与行为

- 旧项目迁移后六个工作台数据不丢失。
- 新建项目只需四项轻量字段，创建后成为当前项目。
- 初始草稿在提交新建表单时原位补全，不产生重复项目；项目库始终至少保留一个项目。
- 旧项目库缺失 `onboardingComplete` 时不会错误进入首次引导。
- 根地址进入项目桌面，六种 `workspace` 深链接行为保持不变；项目桌面自动保存不覆盖 `activeWorkspace`。
- 六个摘要适配器对空、已配置、未知版本和损坏数据返回稳定结果。
- 异步封面加载不会产生陈旧预览或泄漏 Object URL。
- 搜索、筛选、排序、收藏、项目切换和返回上下文正确。
- 项目导入导出、复制、删除和角色素材清理回归测试继续通过。

### 视觉与响应式

- 以确认的融合终稿作为 1440 × 1024 唯一视觉基准。
- 在 1440、1280、1024、820 和 390 宽度截图验收。
- 检查横幅与封面构图、三栏比例、字体层级、状态色、长项目名和空状态。
- 实施截图与视觉稿并排执行 design QA；P0、P1、P2 问题清零后才进入其余商业化功能。

### 交互

- 项目卡片单击选中，独立“继续创作”按钮打开工作台，键盘选择和收藏互不冲突。
- 进入任一工作台后项目保持一致，返回项目桌面恢复上下文。
- 本地写入失败、损坏摘要和缺失影像均可恢复且无控制台错误。

## 非目标

- 不制作公开营销首页。
- 不接入账号、云同步、订阅计费或团队协作。
- 不接入任何生图、视频或音乐模型 API。
- 不新增封面上传、Base64 图片存储或远程图床。
- 不重做六个工作台内部页面。
