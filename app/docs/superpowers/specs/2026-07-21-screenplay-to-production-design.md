# 剧本驱动的 AIGC 影视制作工作台

## 目标

把项目中心从提示词汇总页升级为制作入口。创作者从剧本开始，将每一场戏转化为可追踪、可编辑、可交付的 AIGC 制作任务；不依赖某一个生成平台。

首要用户包括独立 AIGC 创作者、影视与广告制作团队、短视频创作者，以及需要商品图和宣传素材的商业用户。

## 一期范围

一期不接入外部生成模型，也不假装可以自动理解全部剧本。它提供可靠的本地工作流：

1. 建立或导入剧本：支持在线新建、粘贴、`.txt` 与 `.docx` 导入；保留源文件名、原文、版本和更新时间。
2. 解析剧本结构：按场次标题、段落与常见内外景格式生成可确认的场次草稿；识别失败时保留原文并按段落拆分。
3. 生成制作分镜骨架：每场至少一镜，默认 15 秒；镜头有故事动作、角色、场景、道具、画面、镜头和声音字段。
4. 场次生产：每场按四个连续步骤处理：故事、资产、画面、镜头。
5. 项目连续性：角色、场景、道具以可复用的资产条目存在；每个镜头引用资产 ID，而非只复制自然语言描述。
6. 输出：导出当前场或全片的镜头制作清单与模型提示词文本。

## 非一期范围

- 不自动代替用户写出完整可拍剧本。
- 不在本地网页里直接生图、生成视频或存储大体积剧本附件。
- 不在没有用户选择模型、授权和费用控制的情况下调用第三方 AI。

AI 扩写、人物关系分析、镜头建议将作为后续可选的模型适配层：输入和输出都先落到本地项目数据，用户确认后才覆盖草稿。

## 用户流程

```text
新建项目
  -> 选择“剧本”
  -> 上传 / 粘贴 / 新建剧本
  -> 确认自动识别的场次
  -> 建立全片视觉圣经
  -> 逐场进入：故事 -> 资产 -> 画面 -> 镜头
  -> 每镜生成对应生图 / 视频提示词
  -> 汇总导出全片制作单
```

进入项目时，只显示“剧本入口”和已有场次数量；没有场次前不显示复杂的制作表单。用户进入单个场次时默认停在“故事”，按需要再展开资产、画面、镜头。

## 页面与组件

### 1. 剧本入口

- 三种来源：`新建剧本`、`粘贴文本`、`上传文件`。
- 支持文件：`.txt`、`.docx`。不支持的类型给出明确提示，不清空当前剧本。
- 显示剧本名称、来源、字数、场次数、最后修改时间和版本。
- 主要按钮为“分析并生成场次草稿”。
- “扩写 / 编写”先以大纲、场次目标、人物目标、对白草稿四种本地写作模板出现；模型接入后同一位置提供“AI 建议”，不直接替换正文。

### 2. 场次确认台

- 左侧是可排序场次列表，显示场号、内外景、地点、时间、镜头数和状态。
- 中间是当前场的四步编辑器。
- 右侧是当前镜头的可复制提示词和完整性检查。
- 重新分析剧本会先显示变更摘要：新增、更新、可能删除的场次；用户确认后才替换。

### 3. 场次四步编辑器

**故事**：本场目的、人物、情绪、行动、冲突、原文片段。

**资产**：角色、服装、场景、道具、车辆等。每项显示状态：`LOCKED_MASTER`、`USABLE_SHOT`、`ALT_REFERENCE`、`NEEDS_FIX`、`REJECTED_HISTORY`。

**画面**：继承或覆盖全片影调、光影、摄影、画幅和参考片。

**镜头**：镜头卡列表。每张卡含时长、景别、构图、调度、表演、声音、负面限制，以及发送到 15 秒运镜的动作。

## 数据模型

每个项目新增：

```text
screenplay
  id, title, sourceType, sourceFileName, rawText, versions, updatedAt
scene
  id, number, sourceExcerpt, story, assets, lookOverride, shots, status
asset
  id, type, name, status, referenceAssetId, notes
shot
  id, sceneId, duration, purpose, composition, blocking, performance,
  sound, negativeConstraints, linkedAssetIds, promptStatus
```

所有文本和元数据保存在当前浏览器项目库。参考图片沿用现有资产存储；源文件正文转为文本保存，避免在项目 JSON 中保存原始二进制文件。

## 解析与扩写原则

本地解析只做确定性工作：识别 `第 X 场`、`场次`、`INT/EXT`、内外景、地点、时间和段落。它不把猜测当事实。无法识别的人物、动作、道具会标为“待确认”。

写作功能先保证用户可控：大纲扩写、场次目标、人物小传、对白草稿都作为独立草稿版本。未来的 AI 输出必须有来源标记、可预览差异、可采纳或丢弃。

## 失败处理

- 文件为空、过大或格式不支持：不覆盖现有剧本，显示原因。
- `.docx` 无法读取正文：提示用户转换为文本或重新上传。
- 没有场次标题：按空行段落生成待确认场次。
- 重新分析：不直接删除用户补充过的资产和镜头；先做差异确认。
- 某镜头缺角色、场景或动作：提示词允许生成草稿，但标记为“未达到可制作条件”。

## 验收与测试

1. 可导入 `.txt`，可通过粘贴或新建剧本得到相同结构。
2. `.docx` 导入正文可用于解析；失败时原项目保持不变。
3. 中文场次标题、INT/EXT 和无标题段落都能生成可编辑场次。
4. 重新分析不会无提示地覆盖已有场次。
5. 每个场次至少有一个镜头卡；切换场次会切换提示词和资产引用。
6. 一个镜头能送入 15 秒运镜工作台，场景、声音和项目视觉基准都被带入。
7. 1440、1280、1024 与窄屏下，场次列表、四步编辑和提示词区域不互相遮挡。

## 实施顺序

1. 把项目页变成“剧本入口 + 场次确认台”，将当前大表单收进四步编辑器。
2. 加入 `.txt` / `.docx` 本地导入、剧本版本与安全重分析。
3. 加入场次资产清单和资产状态，连接现有角色定妆、影调、运镜工作台。
4. 加入全片镜头清单导出。
5. 最后设计可插拔 AI 写作 / 分析适配层，并在用户选定模型后接入。
