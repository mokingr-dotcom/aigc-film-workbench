# 完整项目生产包 V1 设计

## 目标

让创作者可以把一个可生产的 AIGC 影视项目从电脑 A 完整迁移到电脑 B：剧本、场次、分镜、镜头提示词、角色与场景锁定参考图、角色定妆资产、海报关联素材及已选镜头关键帧都保持可用。导入后的项目作为一个新的本地项目存在，不覆盖来源项目。

这不是视频生成服务，也不导出外部平台的原始视频文件。外部生成链接、模型、Seed 和回填记录会被保留；只有已被项目引用的本地图片资产会被打包。

## 范围

### 包含

- 当前项目的完整结构：项目简介、剧本版本、场次、镜头、镜头提示词、资产锁定、生成回填及状态。
- 项目正在使用的角色定妆图片、海报源图与标题素材、项目参考图片。
- 项目简介的参考图、每个资产锁定项的参考图、每个镜头“已选结果”的关键帧参考图。
- 导入前检查、导入进度、导入结果摘要、失败与部分恢复状态。
- 导入/复制/删除时的引用安全：所有导入资源都是新副本，删除一个项目不能影响另一个项目。

### 不包含

- 外部平台生成的视频或图片文件；只保留其 URL、模型、Seed、备注与选择状态。
- 没有被当前项目引用的素材库内容。
- 多人在线协同、云同步、账户系统和外部模型 API。
- 旧 JSON 备份格式的自动“补图”；它继续作为轻量文字备份存在。

## 用户流程

### 导出

1. 创作者在项目中心点击“导出完整项目包”。
2. 系统先读取当前项目与所有受引用资产，展示预检摘要：剧本版本数、场次、镜头、锁定资产、已选结果、图片数量与估算体积。
3. 如发现引用记录找不到本地图片，导出停止并列出缺失项，不能生成一个表面完整的坏包。
4. 创作者确认后，系统显示具体阶段：检查项目、整理参考图、整理已选关键帧、生成项目包。
5. 浏览器下载一个 `.aigc-project.zip` 文件。

### 导入

1. 创作者在另一台电脑的项目中心点击“导入完整项目包”。
2. 系统在写入任何本地数据前完成预检：格式、版本、文件数量、路径、资源摘要、哈希、图片类型与尺寸、所有引用关系。
3. 通过预检后，系统默认以“新项目副本”导入，生成新的项目 ID 和新的所有资源 ID，并重写项目内的所有指针。
4. 图片先暂存，再提交项目元数据；任何阶段失败都只清理本次新写入内容，不改动已有项目。
5. 完成后显示“已恢复 X 场、Y 镜、Z 个锁定资产、N 个已选结果”，并提示外部链接仅恢复链接记录。

## 包格式

文件扩展名：`.aigc-project.zip`。

```text
manifest.json
project.json
assets/casting/000001.bin
assets/poster/000002.bin
assets/project-reference/000003.bin
```

`manifest.json` 记录固定格式版本、导出时间、来源项目摘要、受控文件清单、每个资源的 MIME、长度、SHA-256、来源存储类型、元数据与使用位置。压缩包内路径只由系统生成的序号组成，绝不使用用户文件名或资源 ID。

`project.json` 是“可迁移投影”：保留全部创作数据与结果元数据；未被选择的生成结果仍保留记录，但其 `keyframeReferenceId` 清空，不携带未选择关键帧图片。

## 数据完整性规则

- 资源集合以“实际引用”为准，去重后打包：角色资产、海报资产、项目简介参考、锁定角色/场景参考、选定镜头结果关键帧。
- 导入一律生成新的项目 ID 与资源 ID，并重写 `referenceAssetIds`、关键帧 ID、角色定妆 ID、海报资产 ID 等所有嵌套指针。
- 导入不得覆盖已存在项目或 IndexedDB 资源；同名项目允许存在，并在 UI 中标注为导入副本。
- 每次导入使用一个临时事务日志：资源写入成功后才提交项目元数据；失败则只回滚本次新资源。下次启动会清理未完成日志。
- 删除或解除锁定之前必须检查全项目库引用；仅在没有其他项目使用时删除真实图片资源。
- 删除场次或镜头后，执行同样的无引用清理，避免长期积累孤儿关键帧与参考图。

## 安全与容量边界

- 仅接受 V1 manifest、`project.json` 和三个受控 assets 路径前缀。
- 拒绝加密 ZIP、绝对路径、路径穿越、重复条目、未知文件、超出文件数或压缩比上限的包。
- V1 限制：单项目包 250 MB、最多 160 个图片资源、单图片 20 MB、`project.json` 最大 2 MB；导入前还验证图片魔数、MIME、解码尺寸与像素上限。
- 哈希、字节数、资源数量或引用任一不匹配时，整个导入失败且不写入项目。

## UI 文案与状态

- 现有“导出备份 / 导入备份”改为“导出轻量备份 / 导入轻量备份”，明确“不含本地图片素材”。
- 新增主操作“导出完整项目包 / 导入完整项目包”。
- 进度使用明确对象与数量，例如“正在检查 6 个锁定资产”“正在恢复第 2 / 8 个镜头”。
- 失败说明必须具体：无效项目包、版本过新、缺少参考图、空间不足、导入已回滚。
- “下载 Markdown”仍是交付文档，明确与完整项目包区分。

## 技术边界

- 新建纯逻辑模块 `project-archive.js`：资源收集、包清单、项目投影、ID 映射、预检与导入计划；同时支持浏览器 IIFE 和 CommonJS 测试。
- 引入固定版本、本地 vendored 的 `fflate` UMD 与许可证，完全离线读写 ZIP，不引入构建系统。
- 各 IndexedDB 存储模块只提供受验证的精确 ID 写入接口，禁止导入器绕过图片验证直接写 Blob。

## 验收标准

1. 一份含剧本、场次、镜头、锁定角色/场景参考图、选定关键帧的项目，可导出为单一项目包。
2. 在清空浏览器数据的另一台电脑导入后，场次顺序、镜头提示词、锁定规则、参考图和已选关键帧均恢复可用。
3. 导入完成项目以新 ID 创建；删除导入副本或来源项目不会影响对方资源。
4. 缺少、篡改、超限或不安全的包在写入前失败，既有项目不受影响。
5. 中断、配额失败或数据库失败后，系统不留下可见半项目，也不泄漏本次暂存资源。
6. 轻量 JSON 备份与 Markdown 交付文件仍可使用，且 UI 中不会被误认为完整项目迁移。
7. 自动化测试覆盖资源精确收集、选定关键帧投影、ID 重写、哈希/路径拒绝、冲突拒绝、导入回滚和删除后引用安全。
