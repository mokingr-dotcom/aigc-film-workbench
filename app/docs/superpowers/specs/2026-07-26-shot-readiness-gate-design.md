# 镜头生成准备清单设计

## 目的

让项目里的每一条镜头在送入外部视频模型前，能一眼判断是否具备稳定生成条件，并能直接去补齐缺失的角色、场景或影像信息。

这是项目页的生产闸门，不是新的工作台，也不调用任何生成模型 API。

## 用户结果

在当前选中镜头的制作区，用户能看到一张“生成准备清单”：

- 本镜是否可以生成；
- 已具备与缺失的生成条件；
- 已锁定的角色、场景与道具资产；
- 每个角色/场景资产是否已有参考图，以及其连续性锁定规则；
- 目标模型、镜头时长和当前制作状态；
- 对每种缺失项的明确下一步入口。

用户不需要在影调、角色、运镜和项目页之间猜测该补什么；清单只给出与当前镜头有关的行动。

## 范围

### 包含

1. 新增纯数据模块，把已有的 `assessShotReadiness`、资产锁定信息和场景字段聚合为镜头准备状态。
2. 将当前 7 项镜头条件分成三组：
   - 叙事与表演：叙事、主体/人物、可见动作；
   - 画面与摄影：地点、影调、景别与运镜；
   - 交付与连续性：声音与限制、目标模型、时长、角色/场景参考资产。
3. 在项目的当前镜头编辑区新增一张紧凑“生成准备清单”，展示状态、缺失原因与下一步按钮。
4. 支持以下明确跳转：
   - 人物缺失：进入角色定妆；
   - 影调缺失：进入影调；
   - 景别与运镜缺失：进入 15 秒运镜；
   - 场景文字缺失：聚焦当前场次地点输入；
   - 已锁定但无参考图的角色/场景资产：聚焦本场资产区的上传入口。
5. 不改变已有的就绪判定、单镜提示词、整场镜头包或整片镜头交付包内容。

### 不包含

- 不自动替用户填入影调、动作或运镜。
- 不上传图片、不自动生成角色图或场景图。
- 不直接发送到 Seedance、即梦、可灵等模型。
- 不把“没有场景参考图”一律视为阻塞：完整的文字地点与场景描述仍可通过基础生成闸门。

## 数据与判定

新增 `project-shot-readiness.js`，提供：

```js
buildShotReadinessGate(project, scene, shot)
```

返回：

```js
{
  ready,
  completion: { complete, total },
  groups: [{ id, label, items }],
  assets: [{ id, kind, name, referenceCount, referenceRule, requiresReference }],
  actions: [{ id, label, target }]
}
```

基础可生成条件继续完全复用 `scene-readiness.js`。资产参考图作为“连续性状态”：已存在时明确展示为已锁定参考；缺失时标记为建议补齐并给出入口，但不篡改当前镜头的 `ready` 结果。这样纯文字场景、临时单镜也能正确工作。

## UI

位置：当前 `SHOT READY CHECK` 之后、分析和编辑表单之前。

结构：

1. 头部：`SHOT GENERATION GATE`、可生成 / 待补状态、`X / Y 项就绪`。
2. 三个检查组：每项显示已就绪或待补，以及条件来自项目母版、本场或当前镜头。
3. 连续性资产行：角色、场景、道具的稳定 ID；对角色和场景显示“参考图 N 张”或“建议补参考图”。
4. 操作区：只出现当前缺失相关的行动按钮，不出现无关导航。

视觉维持当前项目页的浅色制作台风格：状态使用低饱和绿色、琥珀色和灰色，不新增高对比大面板，不挤压镜头编辑表单。

## 异常与边界

- 没有选中镜头时不渲染清单。
- 没有锁定资产时显示“当前镜头尚未锁定连续性资产”，并将其作为建议，不把它误报成基础提示词错误。
- 资产元数据异常、参考图储存缺失或模块未加载时降级为空状态，不影响现有项目编辑与提示词复制。
- 跳转只切换现有工作台或聚焦现有输入，不创建或覆盖项目数据。

## 验收

- 一条已完成的镜头显示所有基础条件，并保持原有可生成判断。
- 人物、影调、运镜、地点任一缺失时，清单显示对应缺口及唯一可执行入口。
- 场景有完整文字描述但无场景参考图时，基础可生成状态不被错误阻塞。
- 锁定人物或场景有参考图时，清单显示参考图数量和一致性规则。
- 没有资产的普通镜头仍能使用既有项目流程。
- 项目工作台窄屏与桌面屏均不遮挡生成准备清单和镜头编辑区。
- 全量回归测试通过，并在本地浏览器验证至少一个待补镜头和一个完成镜头。
